# Windows managed deny-read recovery

This candidate retains the native sandbox and repairs its ACL bookkeeping. It
does not add an agent loop, permission broker, or background supervisor.

The original native path used Win32 REVOKE_ACCESS to remove a deny-read ACE.
That operation removes allow/audit entries, so a profile change could leave
the deny behind while deleting its ledger entry. The controlled
full-read → explicit-deny → full-read run reproduced that failure.

The patch removes only the exact explicit deny-read forms generated by the
native add operation for the recorded principal. It preserves other principals,
allow entries, unrelated write-only denies, and inherited restrictions. A mixed
or otherwise ambiguous read mask is an error and retains ownership bookkeeping.

    stable private OS file lock
        |
        +-- read and validate existing ledger
        |     malformed or linked -> error; preserve existing bytes
        |
        +-- atomically record previous + planned paths
        +-- apply the same validated plan
        +-- revoke only stale managed deny-read entries
        +-- atomically record remaining ownership
        |
        +-- release lock on return or process exit

The fixed sidecar inode is scoped to the ledger's physical parent. Its protected
DACL permits the authenticated user, SYSTEM, and Administrators. Reparse points
and multiple links are rejected. The OS lock spans the complete transaction;
replacing the JSON does not replace the lock. A bounded lock failure stops the
command.

Atomic writes reuse the native temporary-file and pinned-directory writer.
For an existing ledger, the replacement preserves every DACL ACE and its
protection/automatic-inheritance state. The documented user-mode
NtSetSecurityObject operation updates the fresh temporary handle only. An
auto-inherited source DACL carries the corresponding inheritance request bit.
Ownership follows the authenticated creator, as in the native atomic writer;
it is not forcibly reassigned to a previous elevated Administrators owner.

A live destination handle that prevents atomic replacement produces an error
and leaves the original bytes intact. Partial apply, rollback failure, and final
save failure retain the pre-recorded ownership for a later reconciliation.
A malformed ledger requires explicit diagnosis; it is never treated as empty.

## Evidence boundary

Independent Win32 fixtures cover exact ACE preservation and inheritance,
ambiguous-mask rejection, both atomic-save failures, partial apply plus failed
rollback, cold reconciliation, two writers observing the real OS lock through a
home alias, and process exit/crash followed by reuse of the same lock inode.
A Limited interactive process refreshed an elevated-created ledger with its
DACL unchanged. High-created symbolic/hard links were separately consumed and
rejected by Limited calls, with their external targets unchanged.

These component results are prerequisites. The corrected packaged CLI must
also pass the real full-read → deny → restore workflow and final product gates
before the candidate is marked ready. Existing installations are not migrated
or modified by these tests.
