# CDS 0.6.9：Windows 原生会话数据库兼容修复

本版沿用 Codex CLI 0.164.0-alpha.7 的原生 runtime 和固定 DeepSeek 路由，修复同一版 Codex 在 Windows 官方发行包与源码构建包之间的数据库迁移校验差异。缺省模型、工具与权限行为沿用 0.6.8；新增逐 home 的显式普通提供方选择，特殊路由优先级不变。

本版状态以实际发行页和资格索引为准；三平台产物、安装与真实任务分别验收，候选分支或 CI 产物不能代替稳定发布。

## 修复了什么

原生 SQLx 迁移按 SQL 原始字节计算校验和。相同 SQL 的 LF 与 CRLF 换行会产生不同校验和：旧源码构建包创建的 LF 账本与官方 Windows 包的 CRLF 账本不能互读，原生数据库初始化会失败。该问题已有两个方向的真实旧版二进制失败记录。

新增的共用 native 补丁只在迁移入口选择已识别的逐版本 LF/CRLF SQL 形式，然后仍由 SQLx 执行原来的迁移。它覆盖主状态、日志、目标、记忆、队列和线程历史六类原生存储；不改写历史迁移表，不跳过校验，不替换数据库引擎或 runtime 业务逻辑。

新建 Windows 存储使用 Windows 官方的 CRLF 形式。既有一致 LF 或 CRLF 存储保持自身形式，尚未创建的辅助存储继承已确认的主存储形式。未知校验和和未完成迁移仍报错。对已识别的混合形式可按版本恢复，但这不保证未打补丁的旧程序能够读取任意混合账本。

## 升级和回滚

从稳定发布页取得 v0.6.9 的匹配源码及本平台资产，按 README 的标准 install.py 入口安装；安装器仍检查完整归档、recipe 和文件清单。无需用户编译 Rust。

升级前结束自己不再使用的 CDS 任务并保留专用数据目录备份。安装使用不可变版本目录；不能覆盖未知或仍被占用的启动器，也不能全局结束 codex.exe。已有 Codex App 配置、订阅和状态目录不属于本项目的升级对象。

对原本由 0.6.8 源码构建包创建、账本一致为 LF 的已有存储，新版保持 LF，验收单独检查旧版重开。新版新建的 Windows CRLF 存储可由匹配的官方 Windows 原生包读取，但不能据此承诺旧 LF 构建包读取它。回滚程序与回滚数据必须分别判断；不要为了降级手工重写迁移校验和。

## 验收范围

发布资格必须同时核对固定源码、27 份 overlay、精确 recipe、实际二进制和完整包清单。Linux/macOS 的原生状态迁移、Guardian 和 CLI/HTTP 传输测试在各自宿主上执行；Windows 另外用真实新旧二进制交叉打开隔离存储，并核对账本、表结构和用户数据。完整离线适配层、正常安装来源和真实 DeepSeek 任务作为独立证据保留。

旧版原始失败、首次测试失败、平台专用跳过与未执行过滤项都保留在资格报告中；不把它们抹掉或加进通过数量。三平台存储修复资格不等于所有工具在每个平台重新完成一遍，也不代表独立 CADSG 桌面 App 项目已完成。

## 模型、搜索和云端范围

继续使用固定 DeepSeek 模型和显式提供方策略，不因失败暗中更换模型或提供方。新增配置入口见[提供方配置](provider-routing.zh-CN.md)：仅允许 deepseek 与 morph/fp8，活动 home 拒绝修改，设置与服务共享同一锁和不可变快照。上游暂时不可用时显示错误，保留可恢复会话。OpenAI 订阅权益、模型质量和模型自身模态能力不属于本地 runtime 等价范围；金融、体育等 OpenAI 私有云数据服务单列，不冒充本地已接入功能。

安装、权限、搜索、技能、诊断和卸载的通用说明沿用 README 与既有操作方案；本版数据库边界以本文件和实际资格索引为准。
