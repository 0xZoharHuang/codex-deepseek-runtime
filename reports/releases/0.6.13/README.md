# 0.6.13：Windows 私有目录中的原生 Node 执行

Windows 正常安装、原失败目录自动升级及新进程冷启动复测已通过。公开发布和默认下载入口由发布回执另行确认。Linux/macOS 的 v0.6.12 稳定版本继续可用；本版 Unix CI 正在复验，不因 Windows 通过而标成通过。

这个修复针对下游实际遇到的 `node script.js` → `EPERM lstat`。旧的目录属性权限只有 `FILE_READ_ATTRIBUTES`，实际属性句柄还需要 `SYNCHRONIZE`。P37 通过原生 ACL 准备路径补齐精确、不继承的 0x100080 掩码，并分别核对两个沙箱用户的完整权限。原生工具、审批、会话、子智能体与模型请求机制保持原有实现。

验收使用固定 Node 24.22.1 / libuv 1.52.1、同一个 home 和原失败目录。旧版离线/联网两种身份均失败；正常安装的新包在两种身份下均通过普通脚本文件执行，冷启动再次通过。整个升级与冷复测没有手改该目录 ACL，没有用 stdin 替代脚本入口；父目录枚举、写入和实际私有旁文件读取继续被拒绝。

[机器可读资格](windows-runtime-qualification.json)记录版本、原生配方、包与原件哈希、实际限制和未关闭范围。原件保存在维护者隔离验收目录；本公开文件是保留原件摘要的验收报告，不冒充完整原始日志。原生权限单测 29 通过；另有 1 项明确针对独立 CADSG home 的检查未执行、未计入通过。源码配方检查 87 通过、9 项平台条件跳过。

首次 Unix CI 因验收脚本写死 0.6.12 而失败，原[证据](ci-first-failure/)保留。实际安装的 0.6.13 及 32 个模块来源已独立核对。脚本改为对照 `pyproject.toml` 的明确版本，同时加强路径解析，拒绝通过 `..` 逃出安装目录；6 项回归通过。该修复没有放宽版本一致性或模块完整性要求。

编译阶段曾清理准确归属的 MSVC telemetry 子进程，编译生命周期未标为全通过；实际原生测试、安装入口和工具冷启动的退出分别验收。此前 Windows Jinja 业务基准失败、不确定云消费 pin 和其他原始失败均保留。CADSG / Codex App 尚未完成，不由本 CLI 发布代验。
