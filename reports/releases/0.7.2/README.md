# CDS v0.7.2

本次维护更新集中在模型请求的历史回放。Windows 继续使用 v0.7.1 发布的 P41 原生归档，Linux 和 macOS 继续使用各自清单固定的 P35 归档。三平台的归档地址、SHA-256 和原生构建配方保持一致。

- 同一次模型响应的并行工具调用以已完成响应的记录为依据分组，工具 ID、参数和结果保留原值。缺少响应归属证据的历史保持原顺序。
- 原生子智能体的消息保留发送者、接收者、消息类型和正文，以标准消息交给模型。适配器不在工具历史里制造内部工具调用。
- 中断留下的孤立推理和未完成助手输出以带原位置的历史助手数据保留。实际复跑保留了旧 400 回执和改动后的流式完成回执。

原生长图片会话和冷恢复的发布基线见 [v0.7.1 回执](../0.7.1/README.md)。本次回归在单独的安装根和会话目录执行。现有入口可通过 `--no-activate` 保留，`codex-deepseek --version` 显示内置原生 CLI 的版本。

## Windows 发布版长图片补验

在独立的 Windows 安装和会话目录，使用已发布 v0.7.2（`ea904580eb62e074b27753f1095ac643d3c5d2d6`）与固定 P41 原生组件完成实际多文件任务。一次成功请求使用 16 张原图，包含 2 个 File 引用和 14 张内联图，实际序列化请求为 29,796,750 字节。业务输出通过独立校验。通过原生显式压缩后，原进程退役，新进程冷恢复同一个会话并继续读取与原件字节一致的图片。

实测共 25 条 HTTP 200 回执。普通请求显式选择 `morph/fp8`，严格 Schema 请求也走 `morph/fp8`。独立 generation 回读核对了实际 Morph 提供方和固定 DeepSeek V4.1 Flash 20261017。该真实任务未触发 413，自动 413 恢复由各自的独立受控证据覆盖。业务运行前的三次夹具和配置失败随原始记录保留。

私有原始归档有 37 个成员，SHA-256 为 `8d380113cd50670d455340e540624e89034f83c994a5c98ae3b3abe299978645`。首次清理超时后，发布版清理入口按已记录的三个测试文件 ID 恢复，分别确认它们已不存在，剩余 pin、未知资产和未清文件均为 0。恢复回执 SHA-256 为 `83a8f87db9523d08fee3805fe9cf1d6240e0b11b48229f0892d449755f87c601`。

## Windows 发布版受控 HTTP 413 冷恢复

在普通权限 Windows 会话中，以同一 v0.7.2 发布源码和 P41 运行发布版冷恢复用例。隔离的真实本地 HTTP 链路在冷进程收到普通请求时，于流开始前返回 HTTP 413。原生运行时完成压缩后，同一会话和同一恢复 turn 的普通请求返回 HTTP 200。原始会话记录和检查点核对了待处理后缀的字节与顺序，并确认先前工具效果只执行一次。检查点从 epoch 2 推进到 3。

发布版测试自身通过，耗时 36.90 秒。测试后的观察脚本漏导入 JSON 模块，外层调度退出码为 1，保留原始终态。独立回读核对了 JUnit、真实 HTTP 顺序、两个原生进程的自然退出和会话压缩记录。受控故障用例不产生 OpenRouter 请求，上节 25 条 HTTP 200 属于独立的真实长图片运行。

受控用例原始摘要 SHA-256 为 `8e1152d58a30eaa975767f13ffe2ef08df01e3db4a28d208ac3aa9eed1ad5183`。私有原始归档含 89 个成员，SHA-256 为 `452397e322dd314250f44ef71eecf704e9bfe72eb766927d3a98514fae675a3f`。 [发布版测试源码](https://github.com/0xZoharHuang/codex-deepseek-runtime/blob/ea904580eb62e074b27753f1095ac643d3c5d2d6/tests/test_native_payload_retry.py#L765)
