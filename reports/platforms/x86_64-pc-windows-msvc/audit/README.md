# 本次 Windows 验收的只读审计脚本

这 7 个脚本公开本次历史证据的核对逻辑：标准 30 门的明确组合、原始失败的保留、RPC 请求与响应配对、源码和原生产物身份、浏览器与协议恢复，以及两种 Windows 沙箱模式。它们不启动模型，也不修改原始验收结果。

原始实验使用 `D:/CodexDeepSeekQA/20261021`、`D:/CDSQA069` 和独立 Windows 客体目录。脚本中的这些通用任务路径、固定版本、source_id、QA/hash、原始失败和完整范围断言都保持原样。原始私密报告、模型请求/rollout、安装目录和机器连接辅助文件不随本目录公开；没有这些原始材料和配套布局时，不能把脚本直接运行成功当作可用前提。

公开副本只将 5 处机器专属 SID 字符串替换为必填环境变量，并在需要的 3 个文件中增加 `import os`。其余 4 个脚本字节不变。没有默认值或回退：缺少脚本所需的环境变量时检查会失败。

| 环境变量 | 必须对应的身份 |
|---|---|
| `CODEX_DEEPSEEK_QA_STANDARD_SID` | 原始 runtime 验收及私密证据读取所用的专用标准用户 |
| `CODEX_DEEPSEEK_QA_ADMIN_SID` | 原始完整 offline 验收所用的管理员用户 |

环境变量必须来自被核对的原始验收身份，不能随意填入其他账户。脚本仍会交叉检查当前读取身份、artifact 中的身份、安装和原生 manifest、实际 launcher、冻结 QA、原始文件 SHA 及完整验收范围。

`original-to-public-sha256.json` 记录每个原始脚本与公开副本的 SHA、身份参数化数量和语法检查结果。公开副本已经过语法编译与 AST 差异核对，除上述身份输入及 `import os` 外没有语义变更；未执行脚本，也未增加模型或 runtime 实验。历史回执中的原始 `validator_sha256` 继续指向当时实际执行的原脚本，不能换成公开副本的 SHA。

若要在自己的安装上做新的验收，请使用仓库内的 `run_acceptance.py` 和相应 `verify_*.py` 入口，生成属于自己安装、用户身份和版本的新证据。本目录用于审阅固定历史验收的证明过程，不替代这些新验收入口，也不把旧结果改写为新执行。
